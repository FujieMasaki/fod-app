# Focus on Dot Product Scope

この文書は、プロダクトの目的、MVPの範囲、作らないこと、未決定事項の正本である。画面や実装の詳細は
機能仕様、個人データの取扱いは[`privacy.md`](./privacy.md)、構成上の判断は
[`architecture.md`](./architecture.md)を参照する。

## 1. 目的と対象ユーザー

Focus on Dotは、自分の声で日々の考えや感情を振り返り、自分の状態や考えを整理する時間を支える
音声ジャーナリングアプリである。文章を書くより気軽に言葉を残し、後から静かに見返せる体験を目指す。

対象は、日々の振り返りを自分の言葉で残したい人である。より具体的な対象者、医療・支援用途との関係、
他者との共有を扱うかは未決定であり、現在のMVP受け入れ条件には含めない。

## 2. MVPで成立させる体験と完成条件

MVPで目指す一連の体験は、利用者が録音を開始・終了し、内容から生成されたDotを受け取り、
複数のDotを一覧で見渡して過去の自分のDotを選び、振り返れることである。録音から生成までのflowは
[`journaling.md`](./journaling.md)、Dot履歴の範囲と受け入れ条件は
[`dot-history.md`](./dot-history.md)を正本とする。

MVPの完成は、少なくとも次を満たす状態とする。

- 音声入力からDotの生成・保存・振り返りまで、失敗・中断・再試行を含めて利用者が理解できる。
- 音声、生成結果、利用者のデータを誰がどこへ保存・送信し、どう削除するかが決まっている。
- 自分以外のDotへアクセスできず、個人データを不要にresponseやログへ出さない。
- モックによる体験確認と実サービスの挙動を混同しない。
- 今日のDotを大きく見られる。
- 保存された複数のDotを丸として見渡せ、過去の任意のDotの詳細へ到達できる。
- Dotの本文を直せて、消したものを一定期間は取り戻せる。ゴミ箱を経由せず完全削除を要求することもできる。

Dot生成後に利用者が任意で行える深掘り対話は、この基本体験に追加する次段階の機能であり、現行のMVP
完成条件には含めない。体験方針は[dot-follow-up.md](./dot-follow-up.md)を参照する。

## 4. MVP対象外と実装前に決めること

次の体験・機能は現時点のMVP完成条件に含めない。

- 検索、カテゴリ、期間フィルタ、共有・通知、Homeでの最近のDot表示
- DayからWeek / Monthへのズーム表示とアニメーション、週次・月次のAI振り返り
- Dot生成後の深掘り対話の実装（体験方針は採用済みで[dot-follow-up.md](./dot-follow-up.md)を参照、
  実装前の判断は[TASK-018](./tasks/TASK-018-dot-follow-up-dialogue-design.md)）
- 音声Blobまたは文字起こしのbrowser永続化。文字起こしはタブを閉じるまで`sessionStorage`で
  一時保持するだけとし、localStorage等へ残さない（2026-09-28にTASK-002で採用）
- 配送・本人確認・カード決済のために、住所・本人確認書類・カード番号を入力項目として収集する機能
- MFA、passkey、運営者の手動アカウント復旧、メールOTP
- 端末別session失効・全端末logout用DB session、Googleとメールの明示的アカウント連携
- 国内限定の法的・契約上の保証、厳密なD2の個別例外管理

認証方式と公開基盤は[architecture](./architecture.md)のとおり採用した。音声の送信経路と保持・削除は
2026-09-28にTASK-002で採用し、[`journaling.md`](./journaling.md) §2・§4を正本とする。認証の残る細部、
AI provider、prompt、API契約tooling、background job基盤は、MVPを実装する過程で必要に応じて
決める設計事項であり、対象外の機能ではない。既存のdesign-system上の
表現や技術的な実装可能性だけを理由に、候補機能の優先度を確定しない。

Deviseでメール＋パスワード、確認メール、パスワード再設定を扱い、GoogleログインをOmniAuthで
提供する。Railsがpassword・メール配送・不正利用対策の運用を担う。email一致のみでアカウントを
統合せず、本人所有のDotだけを操作できる。通常認証はRails CookieStoreであり、logoutによる
コピー済みCookieの即時失効・全端末logoutは保証しない。期限等の詳細は下記「認証体験」を参照する。
日記内容・音声・AI入力は原則東京とするが、国内限定を利用者へ約束しない。Cookieは利用者端末に
保存され、Google・メール・AIの処理地域は別に確認する。厳密な所在地方針は将来論点に残す。

基盤費は月5,000円を目標とし、安全な公開運用のため月1万円前後を許容する。音声保存・文字起こし・
AI・通信量は別従量予算。ECS複数タスク・RDS Multi-AZ・CloudFront等は、負荷・障害状況・費用を
見て追加する。公開前にPricing Calculator・AWS Budgets・Cost Anomaly Detectionを整える。

### 認証体験（2026-09-25採用、未実装）

録音前にログインし、自分専用端末でも認証成功から7日で入り直す。利用による期限の自動延長は
しない。共有端末向けの短期モードはMVPに含めず、ログイン画面で自分専用端末向けであることを示す。
確認メールは24時間、再設定は6時間で、再送制限と登録有無を明かさない受付応答を設ける。
期限切れは再送・再ログインへ案内する。メール/password変更・退会では本人の再認証を求める。

Google/email一致で統合しない。Googleが確認済みとしたメールが既存のメール登録と一致した場合は、
メールでのログインを案内する。将来の連携は既存アカウントへのログインと双方の認証後に行う。
端末一覧・個別/全端末logoutはMVPに含めず、紛失端末を即時切断できない制約を受け入れる。
利用者/実装への影響、Devise標準との差、代替案と残判断は
[TASK-001 Plan §50–57](implementation-plans/2026-09-21-task-001-identity-design.md)を参照する。

## 6. 文書を追加する基準

独立した振る舞い、データの正本、受け入れ条件、または重要な未決定事項が増えた機能には、機能仕様を
追加する。画面・Componentごとに機械的な文書は作らない。既存仕様を変えるコード変更では、同じ変更で
関連する現行文書を更新する。
