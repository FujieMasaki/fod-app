# Focus on Dot Product Vision

この文書は、Focus on Dot（FoD）の存在理由と長期的な方向性を扱う。ここに書かれた内容はMVPの
実装要件ではない。現在実装する範囲の正本は[`product.md`](./product.md)と関連機能仕様である。

## 1. Why

FoDは「AIが要約してくれる音声ジャーナリングアプリ」を作ることを目的としない。録音・文字起こし・
要約・AIからのフィードバックは、汎用AI（ChatGPT / Claude / Gemini）が今後さらに自然に代替できる
領域であり、そこを競争力にすると長期的に弱い。

実際に価値を感じているのは、記録が積み重なり、後から俯瞰することで日々では気づけない自分の変化に
気づけることである（例: 日々の音声ジャーナリングをNotebookLMで月単位にまとめて振り返る体験）。

## 2. Core Value

**話すだけで、日々の記録が積み重なり、後から自分の人生の流れを眺められること。**

Dotは1回の記録を表す。ユーザーは入力時に分類や整理を求められず、ただ話す。整理・関連付けは後から
AIが行う。

## 3. 競合しない領域と競争する領域

| 領域 | 方針 |
| --- | --- |
| AIモデルの性能（要約・文字起こし・感情分析・分類の精度） | 競合しない。裏側のAI providerは差し替え可能なものとして扱う。 |
| 汎用データベース（Notion等への蓄積） | 競合しない。単に記録を貯めるだけならNotionでも代替できる。 |
| データ構造（Dot・時間軸・カテゴリー・人物の関連付け方） | 競争領域。 |
| 時間軸のUX（Day / Week / Month / Yearで人生を眺める体験） | 競争領域。 |
| 「ただ話すだけで整理される」UXと振り返り体験そのもの | 競争領域。汎用AIを開く目的（相談・作業）とFoDを開く目的（自分を見に行く）は異なる。 |

## 4. データ思想（仮説）

Dotが原本であり、カテゴリー・人物タグはDotを後から見るための切り口である、という仮説を持つ。
採用する場合はカテゴリー分類のためにDotをコピーしない案（1 Dotが複数カテゴリー・複数人物タグに
属する）を比較対象とする。実際に採用するかとその設計は、カテゴリー・人物タグの実装を検討する
段階で、代替案と合わせて機能仕様（未作成）で判断する。この文書の記述だけで設計を確定しない。

## 5. Future（現在のMVP範囲外）

カテゴリーによる横断的な振り返りは、[`product.md`](./product.md)の「将来候補」区分に既に含まれる。
人物タグによる横断的な振り返り、写真・動画のDotへの関連付け、年間ダイジェスト生成は、MVP範囲外の
将来機能候補として[`future-candidates.md`](./future-candidates.md)に蓄積し、まだ`product.md`の
「将来候補」区分には反映していない。時間軸を俯瞰する方向性は`product.md`の「将来候補」区分、
および[`dot-history.md`](./dot-history.md) §4の「Dot → Line → Pattern」という将来構想と重なる。

## 6. この文書とMVPの関係

この文書はプロダクトの方向性を示すNorth Starであり、そのまま現在の実装要件を意味しない。将来構想を
明示的な仕様変更なしにMVP要件へ昇格させない。現在実装する範囲の正本は[`product.md`](./product.md)と
各機能仕様である。
