# Dot History Specification

この文書は、保存された複数のDotを見渡して過去のDotへ戻る体験を扱う。MVP全体の範囲は
[`product.md`](./product.md)、録音からDot生成までの仕様は[`journaling.md`](./journaling.md)を参照する。

## 1. Dotのモチーフ

Focus on Dotでは「Dot = その日の自分」を、UIで丸として表す。1日をひとつのDotとして見渡し、
時間が積み重なるとDot同士の関係や変化が見えてくる体験を目指す。これは表示上のコンセプトであり、
同日に複数回録音した場合の保存件数や統合方法はまだ決めない。

- Dotを単なる記録件数として扱わず、詳細を開かなくても時間の積み重ねを感じられるようにする。
- 色や大きさから感情を決めつけず、過去を評価する表現にしない。
- 演出より、振り返りやすさと現在地の分かりやすさを優先する。

## 2. MVPで必要な履歴体験

- 認証済み利用者が自分の保存済みDotを複数件見渡せる。一覧から過去の任意のDotを選び、その内容を振り返れる。件数が増えても過去のDotへ到達できる。
- Dayでは今日のDotを大きく表示する。そこから過去のDotの一覧へ進める。
- 一覧では各Dotを丸として表し、日付と選択対象を判別できる。色やサイズだけに意味を依存させない。
- Dotがない状態、読み込み失敗、選択したDotを取得できない状態を、実際のデータ状態と矛盾せず示す。
- 他人のDotを一覧や詳細から取得できない。認証・認可、保存・削除の共通条件は`product.md`と`journaling.md`に従う。

一覧の厳密な配置、並び順、日付境界、同日の複数録音、記録のない日の表現は、実装前に決める。
検索、カテゴリ、期間フィルタは、このMVP受け入れ条件に含めない。

## 3. 時間軸の検証候補

Dayで今日のDotを見る体験を起点に、次の時間軸表現を`Concept → Prototype → User Test → 採用判断`
で検証する。Week / Month表示とズームの動きはMVP完成条件ではない。

| 視点 | 表現案 |
| --- | --- |
| Week | Dayから視点を引き、1週間を7つのDotで見渡す。Dayで選択していたDotを見失わない。 |
| Month | さらに視点を引き、約1か月のDotを俯瞰する。 |

時間軸の切り替えでは、iPhone Photosのように視点が引いていく感覚を参考にする。DayからWeek、
WeekからMonthへ進んでも、選択中のDotと時間のつながりが分かることを優先する。左端への配置、
タブ・ピンチ・スクロールの操作、具体的なアニメーションは未決定である。動きを減らしたい利用者への
配慮も採用判断に含める。

プロトタイプでは、Dotの集合から時間の積み重ねを感じられるか、切り替えが分かりやすいか、
動きや丸いモチーフが振り返りと情報の読みやすさを助けるかを確認する。

## 4. AIによる振り返りの段階

MVPは個々のDotに対する日々の振り返りを扱う。週次の「今週のDotから見えてきたこと」と月次の
「今月の変化や繰り返していたテーマ」は将来候補とする。長期的には`Dot → Line → Pattern`、
すなわち日々の自分、複数Dotのつながり、長期的な傾向という体験を検討する。

## 5. 未決定事項

- 同じ日に複数回話した場合も表示上・保存上ともに1つのDotとして扱うか
- 記録のない日の表示、日付境界のタイムゾーン、履歴の並び順
- Dotの色・サイズに意味を持たせるか、線で結ぶか
- Weekの開始曜日、Day / Week / Monthの操作とアニメーション
- 週次・月次AI振り返りを読みたいと感じるか、採用する場合の生成・保存方法

これらを未決定のまま実装へ持ち込まない。MVP一覧に直接必要な事項は、関連するImplementation Planで
決めてから実装する。
