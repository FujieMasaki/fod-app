# フロントエンド AIコードレビュー指針

Focus on Dot のフロントエンドコードレビューにおける運用ルールと観点を定義する。
バックエンド固有の指針は `docs/code-review/backend/` に分離して管理する。レビュー品質を
継続的に改善するため、このディレクトリは生きたドキュメントとして扱う。

## 1. 運用

- レビューは原則として全差分を対象にする。差分だけで判断できない場合は、関連する
  コンポーネント、hook、型、テスト、設定も確認する。
- レビュー開始時に必ず [`security.md`](./security.md) を読む。セキュリティは最重要
  観点である。
- 指摘には重大度、該当ファイル・行、根拠、具体的な修正案を付ける。十分な根拠を
  得られないものは「要確認」とし、断定しない。
- Critical、High、Medium の指摘がなければ `LGTM` と明記する。無理に改善案を
  捻出しない。
- ローカルで依頼されたレビューはチャットへ出力する。ユーザーの明示的な依頼なしに、
  プルリクエストへの投稿や承認は行わない。
- 見落としや継続的な誤検知が判明したら、この README または該当観点ファイルを
  更新する。

## 2. 重大度

| 重大度 | 定義 | 対応 |
| --- | --- | --- |
| 🔴 Critical | 情報漏洩、不正操作、録音データの意図しない外部送信などに直結する | マージ前に必ず対応 |
| 🟠 High | 悪用または重大な不具合につながる可能性が高い | 原則マージ前に対応 |
| 🟡 Medium | 限定的な影響、保守性、または防御の不足 | 対応を推奨 |
| 🔵 Low | 軽微な改善提案 | 任意 |

## 3. 変更種別ごとの確認

| 変更内容 | 最低限確認する観点 |
| --- | --- |
| すべての変更 | `security.md` |
| `src/features/recording/**`, `src/libs/audio/**` | 権限要求、録音データの保存・送信・破棄 |
| `src/features/session/**` | `localStorage` の保存対象、スキーマ検証、リセット |
| API、fetch、外部SDKの追加 | 認証・認可、レスポンスの最小化、エラー、URL検証 |
| `.env*`、設定、依存、CI変更 | 秘密情報、公開設定、サプライチェーン、権限 |
| UIでのHTML・URL表示 | XSS、危険なスキーム、open redirect |

## 4. レビュー出力

各指摘は次の形式を使う。

```text
🔴 [タイトル]
場所: src/path/file.ts:12
問題: なぜ危険または不正確か。
修正案: 実装可能な修正方法。
確信度: 高 / 中 / 低（低い場合は確認すべき前提も書く）
```

良い点はレビュー全体の短いサマリにのみ記載し、修正を要する指摘と混在させない。
