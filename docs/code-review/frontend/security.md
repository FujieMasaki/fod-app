# 観点: セキュリティ 🔴

Focus on Dot は現時点で Vite によるクライアントSPAである。したがって、クライアントへ
届くコード・値は利用者が取得できる前提で扱う。サーバー、認証、外部APIを追加する変更
では、クライアント側の制御を安全境界とみなさない。

## 1. 秘密情報と設定 🔴

- [ ] APIキー、アクセストークン、パスワード、秘密鍵、内部専用URLがソースコード・
  テスト・モック・コミット対象ファイルにハードコードされていないか。
- [ ] `VITE_` prefix の環境変数に秘密情報を入れていないか。Vite はこれらをクライアント
  バンドルへ公開する。
- [ ] `.env`、`.env.local`、秘密鍵ファイル、実運用の設定値が差分に含まれていないか。
  必要なら `.env.example` に値を入れないプレースホルダーのみを追加する。
- [ ] 依存追加、CI設定、GitHub Actions の変更で、トークンをログ出力・第三者スクリプト・
  不要な権限へ渡していないか。

## 2. 録音とブラウザ保存 🔴

- [ ] マイク権限を必要なユーザー操作の後にだけ要求し、拒否時の動作を安全に処理しているか。
- [ ] 録音データ・文字起こし・セッション情報を、要件を超えて `localStorage`、
  `sessionStorage`、IndexedDB、URL、ログへ保存していないか。
- [ ] 保存するデータを最小化し、リセット・削除操作で期待どおりに消去するか。
- [ ] ブラウザ保存データは利用者が改ざんできる。保存値を権限、課金、本人性、または
  サーバーで信頼する値の根拠にしていないか。

## 3. API、認証、認可 🔴

- [ ] 新しい API 呼び出しで、ユーザーや録音データを送る先、送る目的、送る項目が最小か。
- [ ] 認証・認可はサーバーまたは信頼できるバックエンドで検証されるか。UI上の非表示、
  ルートガード、`localStorage` のフラグだけに依存していないか。
- [ ] APIレスポンス・エラーをそのまま画面やログへ出さず、内部情報、トークン、他人の
  データを返却していないか。
- [ ] レスポンスはスキーマで検証し、必要なフィールドだけを利用するか。

## 4. 外部入力・表示・遷移 🟠

- [ ] `dangerouslySetInnerHTML` を使う場合、信頼できないHTMLをサニタイズしているか。
- [ ] ユーザー入力、APIレスポンス、`localStorage` 由来の値を HTML として解釈させて
  いないか。
- [ ] 外部URLを `href`、`src`、リダイレクトに使う場合、許可するプロトコル・ホストを
  検証し、`javascript:` などの危険なスキームと open redirect を防いでいるか。
- [ ] 新しい外部リソースを読み込む場合、必要性、信頼性、送信されるデータを確認したか。

## 5. ログとエラー 🟠

- [ ] `console.*`、監視SDK、例外メッセージに録音内容、個人情報、トークン、APIレスポンス
  全文を出力していないか。
- [ ] ユーザー向けエラーは安全で理解可能な文言にし、調査に必要な詳細は機密を除いて
  分離して記録しているか。

## 6. 現在の構成での補足

- `apps/web/src/features/session/session-context.tsx` の `fod.session.v1` は、セッション復元のための
  クライアント保存であり、セキュリティ境界ではない。保存項目を増やすレビューでは、
  個人性・機密性・削除要件を必ず確認する。
- まだバックエンド実装は存在しない。バックエンドの認証・認可・CSRF・CORS・
  レート制限は、実装追加時に `docs/code-review/backend/` の指針として管理する。
