# Focus on Dot Design System

この文書は、Focus on DotのUIを実装・変更する際のデザイン基準とする。
ユーザーが自分の言葉に集中し、蓄積したDotへ静かに戻れる体験を優先する。

## デザイン思想

- 静けさと余白を大切にする。画面の要素を増やす前に、ユーザーの目的に必要かを検討する。
- 主役はユーザーの言葉。装飾、AIの存在感、操作部品が内容より目立たないようにする。
- 情報階層は、まず配置・余白・タイポグラフィで表現する。
- 一般的な「AI SaaS風」の、角丸カード・影・グラデーション・装飾アイコンが並ぶ画面を避ける。
- 静けさを理由に可読性や操作の発見しやすさを犠牲にしない。文字のコントラスト、フォーカス表示、操作領域を確保する。

## 装飾の制約

| 要素 | 原則 | 使用できる場面 |
| --- | --- | --- |
| Card | 情報のまとまりをすべてカードで囲わない。Homeの最近のDotやDot一覧は、まず余白で区切った行として設計する。 | 独立した操作・選択対象など、面として分ける意味がある場合。 |
| shadow | 装飾目的では使用しない。カードやボタンへの常設の影を標準にしない。 | Dialogなど、重なりや浮いた階層を伝える必要がある場合に最小限。 |
| gradient | 原則使用しない。背景、見出し、CTAに華やかさだけを目的として追加しない。 | 明確なブランド上・機能上の理由を、この文書に記載できる場合のみ。 |
| icon | 意味のない装飾アイコンを追加しない。文章やラベルをアイコンだけで置き換えない。 | 検索、閉じる、戻るなど、操作の理解を助ける場合。単独のアイコンボタンにはアクセシブルな名前を付ける。 |
| border | すべての行・セクション・コンテナを枠線で囲わない。 | 入力欄、必要な区切り、選択状態など、境界や状態を伝える場合。 |
| rounded | 大きな角丸やピル形状を全要素に適用しない。入れ子の角丸パネルを増やさない。 | 入力や操作部品は用途に合う既存トークンを使用する。正円はDotなど、形自体に意味がある場合。 |

トークンが存在すること自体は、装飾を使う理由にならない。
フォーカスリングやエラー表示など、操作に必要な視覚的手がかりは維持する。

## タイポグラフィと余白

- 画面見出し、セクション見出し、Dotのタイトル、補助情報の順に、文字サイズ・ウェイト・配置で階層を作る。
- 太字、大文字、広い字間を多用しない。日本語の読みやすさと自然な改行を優先する。
- 日付やカテゴリ・気分は補助情報として小さく表示する。ただし、小さすぎる文字や薄すぎる色で読みにくくしない。
- 本文には十分な行間を設け、広い画面でも一行が長くなりすぎない幅に収める。
- 関連する情報同士の間隔は小さく、別のDotやセクションとの間隔は大きくする。
- 余白は既存のスペーシングトークンから選び、画面ごとに任意の値を増やさない。
- 狭い画面では自然に縦へ流し、横スクロールや文字の重なりを避ける。余白のために一覧の見渡しやすさを損なわない。

## StylingとDesign Token

- 新規UI・UI変更の標準は **Tailwind CSS v4** とする。CSS Modulesは原則として新規採用しない。
- 色、余白、文字、角丸、影などは **CSS VariablesによるDesign Token** で管理する。
- 既存の `apps/web/src/design-system/tokens/tokens.css` の `--fod-*` を基準とし、同じ意味のトークンを重複定義しない。
- Tailwindから既存トークンを参照できるようにし、役割が分かるユーティリティで使用する。任意の色・余白・影を画面内に直接追加しない。
- 新しいトークンが必要な場合は、用途と既存トークンで表現できない理由を明確にして、共通の定義へ追加する。
- ブランド色や書体の具体値は既存トークンを踏襲する。この文書だけを根拠に新しい配色・書体を導入しない。

### 既存実装との関係

本書作成時点ではCSS Modulesによる実装があり、Tailwind CSSは未導入。
上記は今後の実装方針であり、移行が完了したことを意味しない。
導入・移行はUI実装の変更範囲に応じて扱い、文書追加だけを理由に全画面を書き換えない。
既存の影・大きな角丸・マイク用グラデーションのトークンも、新しいUIへの使用許可を意味しない。
関連UIを変更する際は本書の制約に照らして見直す。

## shadcn/uiの使い方

- 必要なPrimitiveのみ利用する。Dialog、Select、Dropdown Menu、Tabs、必要に応じたDate Pickerなど、アクセシビリティや操作実装が複雑な部品を中心とする。
- shadcn/uiのデフォルトデザインをそのまま使用しない。色、余白、文字、角丸、影をFocus on Dotのトークンと本書の制約に合わせる。
- 見た目を変更しても、キーボード操作、フォーカス管理、適切なラベルなどを損なわない。
- Home、Dot一覧、Dotの表示、ジャーナリング画面など、プロダクト固有のUIとレイアウトはTailwindで組み立てる。
- コンポーネントが用意されていることを理由に、不要なCard、Badge、アイコンを追加しない。

## 画面ごとのUI原則

### Home：最近のDotへ戻る

- 最近のDotを新しい順に **3件** 表示する。3件未満の場合は存在する件数を表示する。
- 各Dotには **日付** と **タイトルまたは1行要約** を表示する。
- その日の **カテゴリや気分がある場合は小さく表示** する。未設定の項目を埋めるためのバッジや記号は追加しない。
- **本文全文は表示しない**。長いタイトル・要約は一覧の高さを圧迫しないように省略し、詳細で確認できるようにする。
- **タップで該当するDot詳細へ遷移** する。リンクとして実装し、キーボードでも移動できるようにする。
- 日付と補助情報を控えめに添えた行を基本とし、余白と文字で区切る。3件をそれぞれ大きな装飾カードにしない。

表示の構成例（文言・日付は例）：

```text
最近のDot

9月13日
今日は少し、自分のペースで進めた
仕事 · 落ち着いた気分

9月12日
帰り道で気づいたこと

9月11日
話してみて整理できた気持ち
暮らし
```

### Dot一覧：蓄積したDotを探す

- 蓄積された **すべてのDot** をたどれるようにする。表示件数を分割して読み込む場合も、過去のDotへ到達できるようにする。
- Dotを **検索** できる入力欄を設ける。
- **カテゴリ検索** を利用できるようにする。
- **年・月・週で絞り込むフィルタ** を設ける。選択中の期間とカテゴリが分かり、解除できるようにする。
- 検索、カテゴリ、期間の操作は一覧の上部に整理し、Dotの内容より目立つ大きなパネルにしない。
- 行の情報量と余白を揃え、**スクロールしやすい一覧** にする。不要な入れ子スクロールや、Dotごとに高さが大きく変わる表示を避ける。
- 日付、タイトルまたは短い要約を軸とし、カテゴリ・気分は補助情報にする。Homeと共通の表示規則を使用する。
- 検索結果がない場合は、その状態と条件の変更・解除方法を簡潔に示す。

検索対象のフィールド、週の開始曜日、期間境界のタイムゾーンなどの振る舞いは、別途プロダクト仕様で定義する。本書では新たな仕様として確定しない。

## UI変更時の確認

- ユーザーの言葉が装飾より先に目に入るか。
- カード、影、グラデーション、枠線、角丸、アイコンに明確な用途があるか。
- 余白とタイポグラフィで情報階層を理解できるか。
- 既存Design Tokenを再利用し、shadcn/uiの初期スタイルを調整したか。
- Homeの3件・表示項目・詳細導線、Dot一覧の全件アクセス・検索・カテゴリ・年/月/週フィルタを満たすか。
- 小さな画面、長いタイトル、データなし、キーボード操作でも読みやすく操作できるか。
