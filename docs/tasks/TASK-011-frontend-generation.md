## 目的と作業範囲

暫定の本文なしPOST /dotから正式な音声・生成契約へ接続し、Processingから保存済みDotの表示までを実サービスに対応させる。既存のschema検証と表示を活用する。モックとの区別、ErrorStateの保存済み文言と実際の音声保持の不整合を同じタスクで解消する。

## 確認可能な完了条件

- [ ] TASK-010から受けた入力を正式契約で渡し、生成・保存の結果をschema検証して表示状態へ反映する。
- [ ] 送信失敗・生成失敗・保存失敗・中断を実際の状態と矛盾せず表示し、再試行可能な操作と再録音が必要な場合を案内する。
- [ ] 「音声は保存されています」という現行文言を、実際の保持状態に一致する表示へ変更し、存在しない音声を再送できるように見せない。
- [ ] 再試行時の識別子や非同期の状態取得は決定済み契約に従い、二重操作・遅延response・画面離脱で別の結果を誤表示しない。
- [ ] 固定mockによる体験確認と実サービスを利用者・検証者が混同しない。設定不足時に実サービスで生成・保存したように見せない。
- [ ] 保存済みDotをDay / 詳細表示へ渡せ、journalingとarchitectureの現行記述を実装に合わせて更新している。
