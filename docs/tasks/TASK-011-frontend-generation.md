## 目的と作業範囲

暫定の本文なしPOST /dotから正式な音声・生成契約へ接続し、Processingから保存済みDotの表示までを実サービスに対応させる。既存のschema検証と表示を活用する。モックとの区別、ErrorStateの保存済み文言と実際の音声保持の不整合を同じタスクで解消する。

## 確認可能な完了条件

- [ ] TASK-010から受けた入力を正式契約で渡し、生成・保存の結果をschema検証して表示状態へ反映する。
- [ ] 送信失敗・生成失敗・保存失敗・中断を実際の状態と矛盾せず表示し、再試行可能な操作と再録音が必要な場合を案内する。
- [ ] 「音声は保存されています」という現行文言を、実際の保持状態に一致する表示へ変更し、存在しない音声を再送できるように見せない。
- [ ] 再試行時の識別子や非同期の状態取得は決定済み契約に従い、二重操作・遅延response・画面離脱で別の結果を誤表示しない。**生成は非同期で、処理IDによるpollingで結果を取得する**（2026-09-29にTASK-003で採用）。**処理IDは、録音開始操作に対してserverが発行する録音attemptの識別子**で、冪等性keyを兼ねる（2026-09-29にTASK-004の`started_at`採用へ合わせて変更。当初はclient発行のUUIDだった）。**録音開始時にattemptを受け取って保持し、送信時に渡す**（取得・保持・破棄の責務はTASK-010）。**pollingを打ち切ってもJobは止まらず、あとから結果を取りに来られる**ことを前提に画面を作る。
- [ ] **文字起こし全文を受け取ったら`sessionStorage`へ保存し、受領をserverへ知らせる**（削除ACK）。serverはそれを受けて**全文の削除処理を始める**（完了時刻は約束されない。失敗時はserverが再試行する）。**ACKの送信に失敗しても利用者の操作を妨げない**（serverは期限で削除処理を始める）。**画面で「削除しました」と断定しない。**`sessionStorage`はタブを閉じる・logout・User切替で消える前提で表示する。
- [ ] **全文が返らない場合の表示を、理由ごとに分けて用意する。「取得に失敗した」と混同させない**。Dotが残るかどうかは理由によって違う。
  - **受領を知らせたあと（ACK後）**: 自分が保存し終えたので`sessionStorage`から読む。serverへ取りに行っても返らない。Dotは残る
  - **保持期間を過ぎた**: Dot（`sentence`と`summary`）は残るので読める。全文だけが読めない
  - **そのDotを完全削除した**: **Dotも残らない。**「削除しました」ではなく、削除処理の状態として示す（完了は約束しない）
  - **退会した**: **Dotも残らない**。そもそも結果を取得する画面に留まらない導線にする
- [ ] 待ち時間の表示で、**消える期限を約束しない**。示すのは「やり直せる期限」（serverが返す日時）までにする。期間と契機は[privacy.md §5](../privacy.md)を正本とする。
- [ ] **録音を送る直前に、整理を始めたときの利用者の世代（`identityEpoch`）を照合し、違えば送らずに録音を捨てる**。整理の画面は開いたときの録音をrefに持ち、利用者が切り替わった後もunmountまで参照するため（2026-10-09にTASK-010の2/2のレビューで追加。[TASK-010 Plan §7-5](../implementation-plans/2026-10-09-task-010-recording-consent.md)）。
- [ ] **録音画面から整理の画面へ移った直後の1回以外は、利用者の操作なしに録音を送らない**。今は整理の画面を開くと生成を自動で始めるため、失敗した後に履歴で戻ると、残っている録音で生成が再び始まり得る（同上）。
- [ ] 固定mockによる体験確認と実サービスを利用者・検証者が混同しない。設定不足時に実サービスで生成・保存したように見せない。
- [ ] 保存済みDotをDay / 詳細表示へ渡せ、journalingとarchitectureの現行記述を実装に合わせて更新している。
