## 目的と作業範囲

個別実装のテストを基に、Web・API・外部AI・端末をまたぐ認証認可と個人データの扱いを実サービス構成で検証する。個別テストを一から重複作成するタスクではなく、境界を越えた漏えい・残存を確認する。問題があれば担当する実装タスクへ戻す。

## 確認可能な完了条件

- [ ] 利用者2人と未認証で、一覧・詳細・生成結果・採用した音声取得経路・更新・削除・ゴミ箱の本人限定条件を確認している。
- [ ] 録音前の説明と、音声・文字起こし・Dot・duration・ログの実際の保存先/送信先/保持期間/削除が一致している。
- [ ] API response、browser storage/cache、ログに不要な個人データやprovider資格情報がなく、利用者切り替えで他人のデータが残らない。
- [ ] **実際に呼んでいる推論経路・リージョンが、TASK-009が記録した内容と一致している**。Transcribeの呼び出し先が`ap-northeast-1`であることも含む（TASK-025が確かめたのは東京でバッチが提供されていることまで。2026-10-21に追記）。録音前の案内に書いた**2つの開示が両方とも実態と一致している。(1) 経路が国内か国外か。(2) 保持や人によるレビューが伴うかどうか**（正本が案内へ求めているのはこの2つで、(2)は**国内経路でも確認する**。正本は[architecture.md](../architecture.md)「データ所在地と費用」。記録の作成はTASK-009、案内の文面はTASK-010）。
- [ ] 削除要求・期限到来・生成中の削除・削除失敗と再実行を経ても、設計に反する残存・復活・誤った完了表示がない。保持期間と削除の契機は[privacy.md §5](../privacy.md)を正本として照合する。音声を預かるS3 bucketのpublic access block・暗号化・versioning・lifecycle・replication・object lockの設定そのものも確認対象にし、アプリの削除が落ちても残り続けないことを確かめる。**versioningが有効だと削除操作が成功してもnoncurrent versionとして実体が残るため、削除後に実体が存在しないことを設定と実データの両方で確認する**。lifecycleの日数は「削除対象になるまで」でその後の削除も遅延し得るため、「24時間で消える」「48時間で消える」のように削除完了の期限を画面や文書で約束していないことも確認する。退会の受理直前に始まったuploadや、S3を読み出し済みのJobが、退会後に音声・生成結果を残さないことも確認する。他人の処理IDやobject keyを指定して再試行・削除・取得ができないことも確かめる。ゴミ箱の中のDotがDay・一覧・詳細・件数に出ないこと、他人のゴミ箱を取得できないこと、7日経過で削除処理が走ること、即時完全削除がゴミ箱を経由しないこと、**アプリの保存領域に編集前の値を持たないこと**（backupに旧値が残ることは別に扱う）も確認する。復元の手順が、削除したDotと編集で取り除いた内容を再公開しないことも確認する。
- [ ] 認証まわりのメール（登録・既登録の案内・確認メールの再送・パスワード再設定・ロック解除）の総送信量を、デプロイ側の上限で抑えている（SESの送信クォータとアラーム、送信元IPごとではなく全体で集計するWAFのrate-based ruleなど）。2026-10-07のセキュリティ監査で、ソースだけでは判定できない要検証として残った項目である。アプリの上限は送信元IPごと・IPと宛先の組ごと・宛先ごとのいずれかで、全体の総量を抑える上限はない。送信元IPと宛先を変え続ければどの上限にも掛からず、ALBがIPv6を受け付けると送信元IPを容易に増やせる前提で判断する。
- [ ] **委託先への9項目の項目8の(b)(c)を、実際のECS環境で確かめている**（2026-10-20にTASK-025で、公開を止めたうえでこのタスクが確かめると決めた）。(b) task roleの一時credentialの取得経路が、アプリのコンテナ以外から使えないよう保護されていること。(c) 侵害を疑ったときにroleのpolicyを無効化しtaskを止める手順があり、実際に行えること。あわせて、公開する時点で、音声を送るアカウントのAI services opt-outのeffective policyが`optOut`のままであることを改めて確かめる。結果を[TASK-003 Plan](../implementation-plans/2026-09-29-task-003-generation-design.md) §26へ記録している。
- [ ] **AWSのサブプロセッサの更新通知が届く状態か、公開の時点で確かめている**（2026-10-21にTASK-025で購読フォームを送信したが、登録の確認メールは無かった）。届いていない場合は購読し直すか、[Sub-processors](https://aws.amazon.com/compliance/sub-processors/)ページのLast Updatedを見て、前回の確認から変わっていないことを確かめる（[TASK-003 Plan](../implementation-plans/2026-09-29-task-003-generation-design.md) §26）。
- [ ] **Transcribeの費用を、長さを偽った音声で使わせられないことを確かめている**（2026-10-27にTASK-009で申し送り。[TASK-009 Plan](../implementation-plans/2026-10-24-task-009-audio-generation.md) §13）。serverは申告の録音時間と大きさしか確かめず、32MBで数時間分の音声を送れる。公開の前に、Transcribeへ送る前にwebm/mp4のcontainerから実際の長さを読み、申告を大きく超える音声を拒否する（別のタスクを起こして実装する）か、残る費用を受け入れる判断を、このタスクのPlanに記録している。
- [ ] **未ログインのmultipartの本文を、回数や同時の数でALB・WAFの側で制限するかを決め、結果をこのタスクのPlanに記録している**（2026-10-27にTASK-009で申し送り。アプリは本文を受け取り終えてから認証を確かめるので、Pumaの上限（34MB）までの本文は未ログインでも受け取る）。
- [ ] 本番の`config.hosts`を公開するドメイン（ホスト名）に設定し、ALBのヘルスチェック（`/up`）が通ることも確かめている。
- [ ] 両領域のレビュー入口とsecurity指針に沿った検証証跡をPlanに記録し、MVP条件に関する未解消の問題・疑いがない。
