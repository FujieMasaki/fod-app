## 目的と作業範囲

TASK-003で選んだ委託先（Amazon Transcribe と Amazon Bedrock）について、学習利用・保持・リージョン等の9項目を一次資料とAWSアカウントの設定で確認し、選定の条件として記録する。**確認していない項目を「問題ない」と扱わない**。公開してよいかの条件（release gate）は[product.md §5](../product.md)の「委託先の確認と公開可否」が正本である。

2026-10-08に、TASK-003の完了条件7をこのタスクへ切り出した。TASK-003の設計判断（provider・実行方式・冪等性・固有名詞の低減・文字起こし結果の置き場）は完了条件1〜6で終わっており、残っていたのはこの確認だけだった。確認は公開前に済めばよい（項目1・3だけは実際に音声を外部へ送る前に要る）。それなのに、TASK-003がDoneでないために、確認と関係のない後続まで止まっていた。切り出した後も、音声を外部へ送るTASK-009はこのタスクに依存させている。opt-outの前に音声を送る事故を依存で防ぐためで、2026-10-08に人間が決めた。経緯は[切り出しのPlan](../implementation-plans/2026-10-08-task-025-vendor-verification-split.md)。

項目ごとの確認先・確認方法・現状は[TASK-003 Plan §26](../implementation-plans/2026-09-29-task-003-generation-design.md)に記録してあり、確認した内容も引き続き同節へ追記する（記録を2か所に分けない）。作業区分を設計判断にしているのは、AWSアカウントの設定と契約資料の確認を人間が行い、未確認や要対応の項目を受け入れるかどうかも人間が判断するためである（定期実行の対象にしない）。

状態をTodoでなくIn progressにしているのは、TASK-003で一部の項目の確認が済んでおり、その作業を引き継いでいるためである。

切り出した時点の状況（詳細は同Plan §26）。一次資料で確認できた項目もあるが、9項目全体の確認、AWSアカウントの設定、日本の個人情報保護法上の評価は済んでいない。Amazon Transcribeは既定では入力がサービス改善に使われ得る（AWS OrganizationsのAI services opt-out policyを適用するまで止まらない）ので、項目1は「問題なし」ではなく「要対応」である。項目6（委託契約）は、AWS DPAがService Termsへ組み込まれ自動で適用されることを確認した。ただし、個人情報保護法上の委託先としての評価は自分たちで行う。項目8（鍵）は、長期固定のキーを持たない設計で一部を解決した。ECSが供給する一時credentialの扱いは確認対象として残る。**確認が済むまで公開しない**。

項目3の「越境する場合に必要な手続き」はTASK-017の結論を待つ。推論が日本国内に収まる経路で運用するあいだは、手続きを対象外と記録して項目3を閉じてよい。ただし越境移転の規律のうち経路を問わない部分（委託先の監督など）はTASK-017が扱い、項目3を閉じてもそちらは残る。TASK-017の結論を受けて国外経路へ変える場合は、その変更の前に改めて確認する。

担当の分け方は同Plan §26「確認の担当と時期」のとおり。次の部分は、TASK-009が使う構成（経路・モデル・設定）を決めてから確かめるもので、TASK-009が行う。**このタスクのDoneには含めない**（含めると、このタスクに依存するTASK-009と互いを待つことになるため）。

- 項目1・2・4のうち、選んだmodel idごとの違い（Bedrockのdata retention mode、保持や人によるレビューが必須かどうか、保存先と閲覧元）
- 項目8の(a)（IAM policyの内容。対象bucketと対象モデルだけを許す最小権限）

このタスクでは、契約資料とアカウント設定の側、およびmodelを選ぶ前に一般的な資料で確かめられる範囲を確認する。越境移転の規律（項目3の手続き）と委託先の監督の扱いは、TASK-017と分担を決めて二重にしない。

## 確認可能な完了条件

- [ ] 委託先に次を確認し、選定の条件として[TASK-003 Plan](../implementation-plans/2026-09-29-task-003-generation-design.md) §26に記録している。**確認していない項目を「問題ない」と扱わない**。
  1. 入力を学習・モデル改善に使わないこと（契約または設定で確認し、証跡を残す）
  2. 保持期間と削除方法（0日が望ましい。保持する場合は期間と削除の確認方法）
  3. 処理・保存のリージョン。越境する場合に必要な手続き
  4. 人によるレビューの有無と条件
  5. サブプロセッサの開示
  6. 委託契約（DPA相当）を結べること
  7. 事故発生時の通知義務と期限（TASK-017の漏えい対応と接続する）
  8. APIキーの最小権限・ローテーション・漏えい時の失効手順（このタスクでは§26の(b)(c)を確認する。(a)のIAM policyの内容はTASK-009）
  9. 第三者認証の有無。あれば参考にするが、これだけを根拠にしない
- [ ] 同Plan §26の「追加の確認対象」（9項目の外）について、確かめる担当（TASK-009・TASK-015）が同節に書かれていることを確認している。実際の構成で確かめる作業そのものは、このタスクのDoneに含めない。
- [ ] 確認の結果をTASK-010の録音前の案内へ渡し、案内が確認結果と食い違わないことを確かめている。TASK-010が未完了なら、確認の結果をTASK-010の関連Plan（なければタスクファイル）へ書き渡したことで満たす。TASK-010が先に完了している場合は、案内を見直す。
- [ ] 確認できなかった項目と要対応の項目について、受け入れるか公開を止めるかを人間が判断し、理由を同Plan §26に記録している。**ただし次の2つは受け入れの対象にせず、済んでいなければこのタスクをDoneにしない**（TASK-009が音声を外部へ送る前の関門だから）。
  - 項目1のTranscribe: AI services opt-out policyを適用し、effective policyで効いていることを確認している
  - 項目3: Transcribeを東京リージョンで使うことと、Bedrockは推論が日本国内に収まる経路から選ぶ方針であることを確認している。実際に選んだ経路が国内に収まることの確認は、TASK-009の完了条件に任せる
- [ ] 確認の結果を[privacy.md §5-1](../privacy.md)の外部provider行に反映している。
