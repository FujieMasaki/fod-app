## 目的と作業範囲

既存のMediaDevices / MediaRecorderによる録音を拡張し、利用者への事前説明と実サービスで必要な入力の受け渡しを実装する。durationだけを渡す現行動作を、決定した音声利用方式に合わせる。生成開始後の状態表示と再試行はTASK-011で扱う。

2026-09-29にTASK-004で、Dotの`date`を`started_at`（録音開始操作をserverが受理した時刻）から算出すると決めた。これに伴い、**実際の録音開始操作でserverが発行する録音attemptを取得・保持し、送信時に渡す・やり直しや離脱で破棄する**責務が本タスクに入る。`started_at`と実際の録音開始のずれを小さく保つため、**マイク権限の取得後、attemptの発行が成功した直後に録音を開始する順序**を守る（発行を待たずに録音を始めたり、録音開始から時間を置いて発行したりしない）。attemptの契約（発行の操作、1件のDot生成にしか使えない制約、期限、別Userでの拒否、保存方式）はTASK-005、決定の経緯は[dot-history §2](../dot-history.md)と[TASK-004 Plan §18-3](../implementation-plans/2026-09-28-task-004-history-design.md)。

## 確認可能な完了条件

- [ ] 録音開始前に音声の送信有無・送信先・保存と削除の扱いと、他人の実名や住所を必要がなければ言い換えられることを確認でき、説明と実際の処理が一致する。
- [ ] マイク権限拒否・非対応を成功した録音として扱わず、次の操作を案内する。対応ブラウザと録音中断時の振る舞いをPlanで明確にする。
- [ ] 録音成功・停止・中断を区別し、決定した音声入力とdurationを生成フローへ受け渡す。必要な形式・サイズの制限を利用者へ示す。
- [ ] 二重停止防止とstream / AudioContext解放の既存動作を維持し、音声Blob・文字起こしをbrowserへ永続化しない。
- [ ] 受け渡せる音声がない場合を明示し、関連するjournalingの現行挙動を更新している。
- [ ] 録音attemptの発行が成功した直後に録音を開始し、発行に失敗した場合は録音を始めずに次の操作を案内する。やり直し・離脱・別Userへの切り替えでattemptを破棄し、古いattemptを別の録音へ使わない。attempt発行から録音開始までの遅れを実機で把握し、Planの前提（遅れが日付境界をまたぐと日付がずれ得る）と矛盾しないことを確認する。遅れの値は仕様として約束しない。
