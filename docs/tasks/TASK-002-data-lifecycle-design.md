## 目的と作業範囲

音声を実サービスへ送るかと送る経路、音声原本・文字起こし・Dot・録音時間・ログの正本、保持・削除を決める。音声Blobと文字起こしのbrowser永続化は採用しない。生成方式はTASK-003と整合させる。編集や利用者の削除要求は、仕様上必要な範囲と操作主体を判断し、未定の画面を自動的に追加しない。

## 確認可能な完了条件

- [ ] データごとの送信先・保持場所・期間・削除主体を一覧化し、保持しないデータも明示している。外部AI側の取り扱いもTASK-003の選定結果と整合している。
- [ ] 音声を送る場合の形式・サイズ制限・upload経路、送らない場合の音声内容を生成へ渡す方法を決めている。
- [ ] 利用者からの削除要求の受け付け方、Dotと音声・生成結果等の削除連鎖、失敗・再試行・生成中の削除時の扱いが決まっている。
- [ ] 録音前に知らせる内容と、失敗後に実際に残るデータ・再送可否を定義している。端末の既存fod.session.v1と実サービスのデータをどう区別・消去するかが決まっている。
- [ ] 固有名詞を含む元音声が最初に外部へ渡る境界を含め、送信・保存・削除のデータフローを説明できる。
- [ ] journalingの「編集・削除」の未決定範囲を確認し、更新可能なデータと手段の要否を明記している。編集UI等の追加が必要なら、まず仕様の採用判断を行う。
- [ ] 決定したMVP条件をproduct / journalingへ反映し、構成上の決定があればarchitectureへ記録している。

## 必要な検証

- 正常終了・停止・中断・送信/生成/保存失敗・再試行・削除について、各データがどこに残るか追跡できること。
- 音声・文字起こしをbrowserへ永続化せず、不要な個人データをresponseやログへ出さない方針になっていること。
