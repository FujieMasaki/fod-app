## 目的と作業範囲

TASK-002で決めた保持期間・削除主体・要求の受け付け方をBackendで実現する。保持期間と削除の契機は[privacy.md §5](../privacy.md)を正本とする。対象はRDSの`dots`（`sentence` / `summary`）、処理中のS3の一時的な音声、**S3の文字起こし結果と対応するAmazon Transcribeのjob**、**処理の記録**、ログである。音声は、Dotの保存まで完了した時点での即時削除、再試行期限（受理から24時間）到来時の削除、Dot削除・退会時の削除連鎖をこのタスクで実装する。Dotの1件ごとの削除はゴミ箱（論理削除）で、受理から7日で削除処理を始めること、ゴミ箱からの復元、ゴミ箱を経由しない即時完全削除もこのタスクで実装する（2026-09-29にTASK-002で採用）。退会はゴミ箱の中も含めて消す。復元の手順には、削除したDotだけでなく**編集で取り除いた内容を再公開しない**条件も含める。編集前の本文をアプリの保存領域へ持たない制約は維持したまま実現方法を決める。S3のlifecycleは取りこぼし用の保険であり、指定した日数は「削除対象になるまで」でその後の削除も遅延し得るため、削除完了の期限としては扱わない。削除の失敗は再実行でき、残存を検知できるようにする。RDSとS3にまたがるので、先にS3を消してからRDSと処理の記録を消し、一部だけ消えた状態を完了と表示しない。退会では、受理以降に新しい保存・再試行・結果の確定が起きないようにし、あとから現れた残存を回収するまで完了としない（排他の方式はTASK-003/005の決定に従う）。処理の記録自体も削除対象に含め、**音声・文字起こし結果・Transcribeのjobの後片付けが終わってから消す**（2026-09-29にTASK-003で確定）。**文字起こし全文は保存しないという前提は取り下げる。**Amazon Transcribeのバッチは結果を必ずS3へ書き出すため、自前のbucketへ出して削除まで管理する。削除の契機は端末の受領通知、期限の到来、Dotの完全削除、退会で、**objectとTranscribeのjobの両方**を消す（jobが非終端の間は削除できないため終端まで追う）。後片付けの失敗は状態を保ったまま再実行し、既に消えている資源への再実行は冪等に成功として扱う。退会の完了条件は行数ではなく**進行中の処理が0であること**とする。アカウント削除画面など決定していない機能を前提にしない。

## 確認可能な完了条件

- [ ] 本人によるDot等の削除要求を決定した手段で扱い、未認証・他人の要求では削除できない。
- [ ] 保持期間に従う削除と、Dot・音声・**文字起こし結果とTranscribeのjob**・生成結果の削除連鎖を、保持するデータについて実行できる。Dot個別削除はそのDotを作った処理の音声と文字起こし結果だけを消し、同じ利用者の他の録音（生成中・再試行待ち）を巻き込まない。退会では本人の分をすべて消す。
- [ ] 削除途中の失敗・再実行・生成中の削除を決定済み方針どおり扱い、削除結果や残存データを誤って完了と報告しない。
- [ ] 削除済みDotが一覧・詳細から取得できず、遅れて完了した生成処理で仕様に反して復活しない。
- [ ] 外部AI側のデータとログも保持方針に従って扱い、制御できる範囲・制約が文書と利用者への説明に一致する。
- [ ] journaling等の関連現行文書へ実装された保持・削除方法を反映している。
