## 目的と作業範囲

TASK-002で決めた保持期間・削除主体・要求の受け付け方をBackendで実現する。対象はRDSの`dots`（`sentence` / `summary`）、処理中のS3の一時的な音声、ログである。音声は、Dotの保存まで完了した時点での即時削除、再試行期限（受理から24時間）到来時の削除、Dot削除・退会時の削除連鎖をこのタスクで実装する。Dotの1件ごとの削除はゴミ箱（論理削除）で、受理から7日での完全削除、ゴミ箱からの復元、ゴミ箱を経由しない即時完全削除もこのタスクで実装する（2026-09-29にTASK-002で採用）。退会はゴミ箱の中も含めて消す。S3のlifecycleは取りこぼし用の保険であり、指定した日数は「削除対象になるまで」でその後の削除も遅延し得るため、削除完了の期限としては扱わない。削除の失敗は再実行でき、残存を検知できるようにする。RDSとS3にまたがるので、先にS3を消してからRDSと処理の記録を消し、一部だけ消えた状態を完了と表示しない。退会では、受理以降に新しい保存・再試行・結果の確定が起きないようにし、あとから現れた残存を回収するまで完了としない（排他の方式はTASK-003/005の決定に従う）。処理の記録自体も削除対象に含める。文字起こし全文は保存しないため削除対象にならない。アカウント削除画面など決定していない機能を前提にしない。

## 確認可能な完了条件

- [ ] 本人によるDot等の削除要求を決定した手段で扱い、未認証・他人の要求では削除できない。
- [ ] 保持期間に従う削除と、Dot・音声・生成結果の削除連鎖を、保持するデータについて実行できる。Dot個別削除はそのDotを作った処理の音声だけを消し、同じ利用者の他の録音（生成中・再試行待ち）を巻き込まない。退会では本人の音声をすべて消す。
- [ ] 削除途中の失敗・再実行・生成中の削除を決定済み方針どおり扱い、削除結果や残存データを誤って完了と報告しない。
- [ ] 削除済みDotが一覧・詳細から取得できず、遅れて完了した生成処理で仕様に反して復活しない。
- [ ] 外部AI側のデータとログも保持方針に従って扱い、制御できる範囲・制約が文書と利用者への説明に一致する。
- [ ] journaling等の関連現行文書へ実装された保持・削除方法を反映している。
