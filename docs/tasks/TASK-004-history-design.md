## 目的と作業範囲

今日のDotと過去の任意のDotを選べるMVP体験に必要な保存・日付・表示のルールを決める。「Dot = その日の自分」はモチーフとして扱い、同日の保存件数・統合方法を推測で固定しない。深掘り対話による更新後のDot表示、最初の生成内容と現在の内容の区別、更新履歴の参照方法は本タスクの対象外とし、TASK-018で扱う。

## 確認可能な完了条件

- [x] 同日の複数録音の保存・表示上の扱い、Dayで今日のどのDotを表示するかが決まっている。
- [ ] 日付境界のタイムゾーン、履歴の並び順、記録のない日とDotが一件もない場合の表現が決まっている。
- [x] Dayから一覧、一覧から詳細への導線と丸いDotの配置・選択方法を決め、日付と対象を色・サイズだけに頼らず判別できる。
- [x] 保存件数が増えても過去の任意のDotへ到達できる取得・表示方法を決め、TASK-005で定義する境界が整理されている。
- [x] 色・サイズの意味付けや線の要否のうちMVP一覧に直接必要な部分だけを決め、感情の決めつけや過去の評価を避ける。
- [x] product / journaling / dot-historyの該当未決定事項を更新し、Week / Monthや検索等をMVP条件に加えていない。

## 採用済み事項と後続への引き継ぎ（2026-09-29、未実装）

**2026-09-29に人間が4件（同日の複数録音・一覧の配置・記録のない日・丸の意味付け）を判断した。**
いずれもPlanの推奨どおり。その後のレビューで、日付境界のAsia/Tokyo固定・0:00 JSTを人間の判断として
記録すべきこと、日付の基準（録音開始時刻か保存時刻か）をTASK-005へ渡さず本タスクで決めるべきことが
分かったため、**完了条件「日付境界のタイムゾーン…が決まっている」を未確認に戻し、状態を
In progressとした**（Plan §18-2・§24のQ5/Q6）。

- 保存は録音1回=Dot 1件の追記のみ。同日の再録音で過去のDotを上書き・統合しない。表示上の
  「1日=1つのDot」は一覧の見せ方であり、保存件数ではない。
- 日付はserverがAsia/Tokyoの暦日として決め、1日の始まりは0:00 JST。録音時刻はUTCで保持する。
  clientの時計・タイムゾーンを日付の根拠にしない。深夜のオフセットは使わない。
  **この境界の確認（Q5）と、日付の基準を録音開始時刻か保存時刻のどちらにするか（Q6）は判断待ち。**
  Q6の結果で`dots`が持つ時刻の項目（`recorded_at`の新設か既存の作成時刻か）が変わり、
  journaling / privacy / architectureのDot定義の更新範囲も変わる。
- Dayは今日の最新Dot 1件を大きく表示する。今日の記録がなければ未記録の案内と録音への導線を示し、
  過去のDotを今日の記録として表示しない。
- 一覧は1日=1つの丸、新しい順、記録のある日だけを詰めて並べる。縦スクロールのグリッドに月見出しを
  置き、各丸に日付の数字テキストと、同日複数なら件数、今日なら「今日」ラベルを添える。
- 丸の色・サイズに意味を持たせず、線で結ばない。選択中・フォーカスは枠線とテキストで示し、
  最小44pxのタップ領域と日付を含むアクセシブルな名前を持たせる。
- 詳細はその日のDotを表示し、同日に複数あれば録音時刻で切り替える（既定は最新）。
- 一覧は日単位の要素を新しい順に返し、続きはcursorでたどる。offset / page番号は使わない。
  日単位の集約はserverで完結させる。任意の月への直接ジャンプは対象外のまま。
- Dot 0件・一覧の読み込み失敗・続きの取得失敗・詳細の取得不可を区別し、取得できないDotを
  別のDotで代替表示しない。
- ゴミ箱の中のDotは日単位の集約にも件数にも含めず、Dayの「今日の最新」にも選ばない。同日の
  すべてがゴミ箱にある日は丸を出さない（ゴミ箱はTASK-002で採用）。
- Week / Month表示とズーム、週次・月次AI振り返り、検索・カテゴリ・期間フィルタ、丸を結ぶ線は
  MVP条件に加えない。Dot本文の編集はTASK-002がMVP対象として採用済みで、本タスクの範囲外。

残る判断は、利用者ごとのタイムゾーン設定、深夜境界のオフセット、同日の複数Dotをまとめる表現で、
[dot-history](../dot-history.md) §5と[product](../product.md) §5に再検討条件付きで残した。
