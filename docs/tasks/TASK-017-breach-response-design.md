## 目的と作業範囲

音声ジャーナルには本人の心身の状態に関する発話が入り得る。要配慮個人情報に当たる範囲、**外国にある委託先で推論を行う場合の越境移転の規律**、漏えい等が起きた場合の報告・本人通知の要否と手順、公開前に受け入れるリスクの範囲を判断する。データを減らす設計上の制約は[privacy.md](../privacy.md)が正本であり、このタスクは「該当したときに何が起きるか」と「公開してよいか」を扱う。

**2026-10-03にTASK-003から論点を1つ追加した。外国にある委託先で生成（推論）を行う場合の越境移転の規律である。**[architecture.md](../architecture.md)「データ所在地と費用」を同日「発話内容の保存と閲覧は日本国内に限る。推論のための一時的な処理は日本国外を許容する」へ変更した。**外国にある第三者への個人データの提供は、委託であっても個人情報保護法第28条第1項の対象になる**（個人情報保護委員会のFAQで確認。整理と出典は[architecture.md](../architecture.md)「データ所在地と費用」を正本とする）。**同文書は2026-10-05に、具体的な手当と付随義務の列挙をやめてこのタスクへ委ねた**（深く調べるたびに次の義務が見つかり続けたため。条文の網羅は一次資料を読む側でなければできない）。**特定すべき内容は下記の完了条件にある**。同文書が負っているのは、確認が済むまで国外経路を使わないという運用条件と、**第28条の手当とは別に重なる義務が2層ある**という事実までである。**(1) 経路や委託先の所在に関わらず要るのが、委託先の監督（法第25条。委託一般にかかる）と安全管理のために講じた措置の公表（法第32条第1項第4号・施行令第10条第1号。保有個人データ一般にかかる）。(2) 委託先またはその再委託先が外国で取り扱う場合に追加されるのが、外的環境の把握（法第23条）と、公表へ外国の名称と制度の概要を含めること**。契約主体が国内法人か外国法人かで第28条の適用と(2)の有無が変わり得るが、**(1)はどちらでも要る**。要配慮個人情報に当たる範囲と重なるため、該当性の判断と同じ場所で扱う。**確認が済むまでは推論が日本国内に収まる経路で運用する**ことを同文書の運用条件として置いてあるので、このタスクは公開の可否を判断する側になる。

すべての感情の記録を要配慮個人情報と扱わない。該当性を過大にも過小にも見積もらず、一次資料で確認した範囲と未確認の範囲を区別する。保持期間と削除の判断はTASK-002、その実装はTASK-013が担当する。一方、漏えいの検知と本人通知は現在どのタスクも担当していない。必要な実装・運用準備・検証の割り当てはこのタスクの成果として決め、既存タスクへ固定的に割り当てたものとして扱わない。このタスク自体で画面・機能を追加しない。

## 確認可能な完了条件

- [ ] 音声・文字起こし・Dotに要配慮個人情報が含まれ得る範囲を整理し、本人が自ら述べた内容と推知情報の扱いを一次資料で確認している。感情の記録一般を該当扱いにしていない。
- [ ] 報告義務の対象となる事態の類型、速報・確報の期限、本人通知の要否・時期・困難な場合の代替措置を一次資料で確認し、本サービスで起こり得る事態に当てはめている。
- [ ] 漏えい等を検知する手段、誰が何を判断するか、報告・本人通知の連絡経路と記録の残し方が決まっている。検知できない範囲を明示している。
- [ ] 決定した対応のうち実装・運用準備・検証が必要なものを、既存タスクの担当範囲と照らして割り当てている。担当がない範囲には新しいタスクを起こし、公開前の検証条件（TASK-015 / TASK-016）へ反映する範囲も決めている。
- [ ] **外国にある委託先へ個人データを渡す場合に必要な手当を一次資料で確認している。**[architecture.md](../architecture.md)「データ所在地と費用」は具体的な条文を列挙せず、特定をこのタスクへ委ねている。**確認できた範囲と未確認の範囲を分けたうえで、少なくとも次を特定している。**
  - **どの手当を採るか**。本人の同意（法第28条第1項・第2項。**事前の情報提供**が付随する）／施行規則第15条の指定国（**最新の指定国を確認する。Q12-1の注記は令和3年9月時点でEUと英国**）／規則第16条の基準適合体制（法第28条第3項の継続的実施の確保と**本人の求めに応じた**情報提供が付随する）／法第27条第1項各号。**付随義務に対応する施行規則の条番号も特定する**（同意ルートは規則第17条第2項〜第4項とFAQ Q12-1に明記があり、基準適合体制側は未確認）
  - **委託先の監督（法第25条）の内容。(1)なので判定の結果によらず決める**。完了条件7（9項目）の委託契約・事故時の通知と重なるので、どちらで扱うかを決めて二重にしない
  - **委託先の運用・保守アクセスの所在と範囲を一次資料で確認し、監督（法第25条）と外的環境の把握（法第23条）でどう受け止めるかを決めている。**[architecture.md](../architecture.md)「データ所在地と費用」が2026-10-05に**所在地要求の「閲覧」の射程から運用・保守アクセスを外し、この2条へ委ねた**ため、その受け皿がここである。**同節は「外国において個人データを取り扱う場合」に当たるかの判定にも運用アクセスの所在を使うので、同じ確認で両方を満たす**。確認できない場合は、確認できない事実と採った前提を記録する
  - **外国の制度等の把握（法第23条）の内容。(2)なので「外国で取り扱う」に当たる場合に決める**。委託先・再委託先が所在する外国の個人情報保護制度等を把握し、それに基づいて講じる安全管理措置を決めている。**公表（下記）はこれら措置の結果を本人へ示すものなので、措置の特定が先にある**
  - **法第32条第1項第4号の公表の内容と手段**。委託先が所在する外国の名称と上記で講じた措置を本人の知り得る状態に置く。**安全管理措置そのものの公表はどの手当を採っても要り、委託先が所在する外国の名称と制度の概要は(2)に当たる場合に追加される。国内サーバを外国から取り扱う場合も(2)に当たる**（FAQ Q10-24）。**外国の名称を特定できない場合の代替情報**も決める
  - **要配慮個人情報が含まれる場合に条件が変わるか**
  - **「提供」に当たるかの判定**。委託先（AWS）との契約主体と、**提供先が個人データを取り扱わない構成**に当たるか（FAQ Q12-3 / Q10-25）。**ただしこの分岐はストレージ側の整理であり、発話内容を推論のために取り扱うBedrockには原則当てはまらない見込みである。当てはまるかどうかをAWSの契約条項で確認する**
  - **判定（「外国で取り扱う」に当たるか、「提供」に当たるか）は、推論経路が国内かどうかに関わらず公開前に終える。**(1)の委託先の監督と安全管理措置の公表は判定の結果によらず行い、(2)の外的環境の把握と外国の名称・制度の公表は「外国で取り扱う」に当たる場合に行う。**どちらも推論経路が国内かどうかでは決まらない**

  国外経路を使ってよいかの結論を人間が判断し、[architecture.md](../architecture.md)「データ所在地と費用」の運用条件へ反映している。
- [ ] 公開範囲（利用者数）と保持期間が、通知の規模と受け入れるリスクにどう影響するかを整理し、公開前に受け入れる範囲を人間が判断している。
- [ ] 決定をprivacy / productへ反映し、TASK-002の保持・削除条件、TASK-003の委託先条件、TASK-015の検証範囲との整合を確認している。

## 必要な検証

- 想定事態の机上演習で、報告対象かの判定、期限内の連絡、本人通知の可否を説明できること。少なくともRDS snapshotやbackupの誤公開、ログへの本文出力、外部AI / 文字起こし側での事故を含める。
- 要配慮個人情報に当たらない場合でも、他の類型（不正目的による行為のおそれ、本人数1,000人超など）で報告対象になり得るかを確認できること。
- 判断結果が、利用者へ約束できない性質を保証する表現になっていないこと。
