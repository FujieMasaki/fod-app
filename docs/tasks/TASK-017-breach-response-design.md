## 目的と作業範囲

音声ジャーナルには本人の心身の状態に関する発話が入り得る。要配慮個人情報に当たる範囲、漏えい等が起きた場合の報告・本人通知の要否と手順、公開前に受け入れるリスクの範囲を判断する。データを減らす設計上の制約は[privacy.md](../privacy.md)が正本であり、このタスクは「該当したときに何が起きるか」と「公開してよいか」を扱う。

すべての感情の記録を要配慮個人情報と扱わない。該当性を過大にも過小にも見積もらず、一次資料で確認した範囲と未確認の範囲を区別する。検知・通知の実装はTASK-013/015、保持期間と削除はTASK-002が担当し、このタスクで画面・機能を追加しない。

## 確認可能な完了条件

- [ ] 音声・文字起こし・Dotに要配慮個人情報が含まれ得る範囲を整理し、本人が自ら述べた内容と推知情報の扱いを一次資料で確認している。感情の記録一般を該当扱いにしていない。
- [ ] 報告義務の対象となる事態の類型、速報・確報の期限、本人通知の要否・時期・困難な場合の代替措置を一次資料で確認し、本サービスで起こり得る事態に当てはめている。
- [ ] 漏えい等を検知する手段、誰が何を判断するか、報告・本人通知の連絡経路と記録の残し方が決まっている。検知できない範囲を明示している。
- [ ] 公開範囲（利用者数）と保持期間が、通知の規模と受け入れるリスクにどう影響するかを整理し、公開前に受け入れる範囲を人間が判断している。
- [ ] 決定をprivacy / productへ反映し、TASK-002の保持・削除条件、TASK-003の委託先条件、TASK-015の検証範囲との整合を確認している。

## 必要な検証

- 想定事態の机上演習で、報告対象かの判定、期限内の連絡、本人通知の可否を説明できること。少なくともRDS snapshotやbackupの誤公開、ログへの本文出力、外部AI / 文字起こし側での事故を含める。
- 要配慮個人情報に当たらない場合でも、他の類型（不正目的による行為のおそれ、本人数1,000人超など）で報告対象になり得るかを確認できること。
- 判断結果が、利用者へ約束できない性質を保証する表現になっていないこと。
