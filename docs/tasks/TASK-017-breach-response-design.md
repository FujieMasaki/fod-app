## 目的と作業範囲

音声ジャーナルには本人の心身の状態に関する発話が入り得る。要配慮個人情報に当たる範囲、**外国にある委託先で推論を行う場合の越境移転の規律**、漏えい等が起きた場合の報告・本人通知の要否と手順、公開前に受け入れるリスクの範囲を判断する。データを減らす設計上の制約は[privacy.md](../privacy.md)が正本であり、このタスクは「該当したときに何が起きるか」と「公開してよいか」を扱う。

**2026-10-03にTASK-003から論点を1つ追加した。外国にある委託先で生成（推論）を行う場合の越境移転の規律である。**[architecture.md](../architecture.md)「データ所在地と費用」を同日「保存は日本国内、AIの推論は日本国外を許容する」へ変更した。**外国にある第三者への個人データの提供は、委託であっても個人情報保護法第28条第1項の対象になる**（個人情報保護委員会のFAQで確認。整理と出典は[architecture.md](../architecture.md)「データ所在地と費用」を正本とする）。**未確定なのは、どの手当を採るか（同等国・施行規則第16条の基準適合体制・法第27条第1項各号のどれか。基準適合体制に依拠する場合は法第28条第3項の継続的実施の確保と本人の求めに応じた情報提供が別に要る）、要配慮個人情報が含まれる場合に条件が変わるか、そして委託先が「外国にある第三者」に当たるか（第28条の起点は提供先の所在なので、AWSとの契約主体が国内法人か外国法人かで適用される条文が変わり得る）である。**最後の点は**国内に収まる経路で運用している場合にも確認が要る**（国内法人なら法第23条の外的環境の把握と法第25条の委託先監督の問題になり得る）。要配慮個人情報に当たる範囲と重なるため、該当性の判断と同じ場所で扱う。**確認が済むまでは推論が日本国内に収まる経路で運用する**ことを同文書の運用条件として置いてあるので、このタスクは公開の可否を判断する側になる。

すべての感情の記録を要配慮個人情報と扱わない。該当性を過大にも過小にも見積もらず、一次資料で確認した範囲と未確認の範囲を区別する。保持期間と削除の判断はTASK-002、その実装はTASK-013が担当する。一方、漏えいの検知と本人通知は現在どのタスクも担当していない。必要な実装・運用準備・検証の割り当てはこのタスクの成果として決め、既存タスクへ固定的に割り当てたものとして扱わない。このタスク自体で画面・機能を追加しない。

## 確認可能な完了条件

- [ ] 音声・文字起こし・Dotに要配慮個人情報が含まれ得る範囲を整理し、本人が自ら述べた内容と推知情報の扱いを一次資料で確認している。感情の記録一般を該当扱いにしていない。
- [ ] 報告義務の対象となる事態の類型、速報・確報の期限、本人通知の要否・時期・困難な場合の代替措置を一次資料で確認し、本サービスで起こり得る事態に当てはめている。
- [ ] 漏えい等を検知する手段、誰が何を判断するか、報告・本人通知の連絡経路と記録の残し方が決まっている。検知できない範囲を明示している。
- [ ] 決定した対応のうち実装・運用準備・検証が必要なものを、既存タスクの担当範囲と照らして割り当てている。担当がない範囲には新しいタスクを起こし、公開前の検証条件（TASK-015 / TASK-016）へ反映する範囲も決めている。
- [ ] **外国にある委託先へ個人データを渡す場合に必要な手当を一次資料で確認している。**委託であっても法第28条第1項の対象になることは確認済みなので、**どの手当を採るか**（施行規則第15条の国・規則第16条の基準適合体制・法第27条第1項各号。基準適合体制に依拠する場合は法第28条第3項の継続的実施の確保と本人の求めに応じた情報提供が付随する。**対応する施行規則の条番号は未確認なので、e-govの施行規則本文で確認する**）、**要配慮個人情報が含まれる場合に条件が変わるか**、**委託先（AWS）との契約主体が国内法人か外国法人か**を確認し、**確認できた範囲と未確認の範囲を分けている。**契約主体の確認は**国内に収まる経路で運用している場合にも行う。**国外経路を使ってよいかの結論を人間が判断し、[architecture.md](../architecture.md)「データ所在地と費用」の運用条件へ反映している。
- [ ] 公開範囲（利用者数）と保持期間が、通知の規模と受け入れるリスクにどう影響するかを整理し、公開前に受け入れる範囲を人間が判断している。
- [ ] 決定をprivacy / productへ反映し、TASK-002の保持・削除条件、TASK-003の委託先条件、TASK-015の検証範囲との整合を確認している。

## 必要な検証

- 想定事態の机上演習で、報告対象かの判定、期限内の連絡、本人通知の可否を説明できること。少なくともRDS snapshotやbackupの誤公開、ログへの本文出力、外部AI / 文字起こし側での事故を含める。
- 要配慮個人情報に当たらない場合でも、他の類型（不正目的による行為のおそれ、本人数1,000人超など）で報告対象になり得るかを確認できること。
- 判断結果が、利用者へ約束できない性質を保証する表現になっていないこと。
