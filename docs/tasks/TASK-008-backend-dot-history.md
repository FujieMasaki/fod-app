## 目的と作業範囲

serverをDotの正本とし、利用者ごとに複数Dotを永続保存してDay・一覧・詳細から取得できるようにする。`sentence`と`summary`の更新と、ゴミ箱（論理削除）による一覧・Day・詳細からの除外もこのタスクの範囲に含む（2026-09-29にTASK-002で採用）。**除外は明示的なscopeで行い、`default_scope`等の暗黙の除外に頼らない。**編集前の値は保存しない。AI生成はTASK-009、保持期限と削除連鎖はTASK-013で扱う。深掘り対話による更新（TASK-018）は本タスクの対象外とする。

## 確認可能な完了条件

- [x] Dotを認証済み利用者に関連付けて永続保存でき、新しいDotの保存で過去のDotが仕様に反して失われない。
- [x] 同日の複数録音、日付境界、表示順を決定済みルールどおりに扱い、Dayに必要なデータを取得できる。
- [x] 本人の一覧と、日付を指定したその日のDot（ゴミ箱の外）を取得でき、件数が増えても任意の過去のDotまで取得を続けられる。対象が0件の日を取得失敗と区別して返せる。
- [x] 未認証や別利用者からの一覧・詳細・更新を拒否し、決定した更新操作がある場合は本人だけが実行できる。
- [x] 必要な項目だけを契約どおり返し、保存失敗と未取得の結果を区別できる。
- [x] 関連する現行仕様・architectureへ実装済み範囲を反映している。
