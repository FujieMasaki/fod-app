## 目的と作業範囲

[dot-follow-up.md](../dot-follow-up.md)で採用したDot生成後の深掘り対話の体験方針を、実装可能な設計に
落とし込む。会話回数上限、終了方法、途中離脱・再開、失敗時の扱いを決め、最初に生成されたDot・対話・
現在のDot・反映されなかった提案・更新履歴（dot-follow-up.md §4のデータ区分）それぞれの保存要否・
範囲・保持期間・削除方法を、TASK-002の保持・削除方針と整合させて確定する。AI provider、音声の保存先、
文字起こし方式、S3の利用、同期/非同期処理の確定はTASK-003の範囲のままとし、本タスクでは扱わない。

## 確認可能な完了条件

- [ ] 1回の深掘り対話の会話回数上限の要否と具体値、終了方法（利用者操作・自動終了）を決めている。
- [ ] 対話の途中離脱時に未承認の変更案・対話内容がどうなるか、中断した対話の再開可否と方法を決めている。
- [ ] 対話中の送信失敗・AI応答失敗・反映時の保存失敗の扱いを、利用者に矛盾なく示せる形で決めている。
- [ ] 対話履歴（データ区分#2）、反映されなかった発言・提案（データ区分#4）を保存するか、保存する場合の
  範囲・保持期間・削除方法を、TASK-002の方針と整合させて決めている。
- [ ] 最初のDot・現在のDot・更新履歴（データ区分#1・#3・#5）のデータモデル、版管理、正本を決め、
  最初に生成された内容を上書きせず参照できることを保証している。
- [ ] Dotを削除した場合の、関連する対話・反映されなかった提案・更新履歴の扱いを決めている。
- [ ] dot-history.mdの一覧・詳細における、更新後のDotと最初の生成内容・更新履歴の表示方法を決め、
  dot-history.mdの該当未決定事項を更新している。
- [ ] 深掘り対話に音声を使う場合の文字起こし・AI providerとの関係を、TASK-003の決定と整合させている。
- [ ] 決定したMVP後の実装範囲をproduct / journaling / privacy / dot-history / architectureへ反映し、
  必要な後続の実装タスク（Backend / Frontend）の要否と範囲を明確にしている。
